# TODO：日志大文件与分析能力

## 目标与现状

日志分析与 Markdown 编辑同为主线。优先让大日志能够分段加载、全文件搜索和定位上下文，内存占用不随文件大小或命中数量无限增长。

大于 50 MiB 的 `.txt`、`.log` 文件使用分块加载，小文件、Markdown 和其他文本继续普通打开。编辑器默认可编辑，只读状态仅由原有开关及用户保存的文档选项控制。界面保留现有底部搜索、高级搜索和结果窗口，不增加操作栏、分段结果面板或底部状态文案。

## 当前实现与边界

- [x] 首次目标加载 50 MiB，底层每次最多读取 5 MiB，UI 每次最多提交 250,000 个 UTF-16 字符；滚动到已加载正文末尾时继续追加 5 MiB，搜索定位可请求追加到命中位置。
- [x] 分块解码保留跨块字符、CRLF 和取消时的读取状态；同一个文件正文连续追加，标签切换暂停读取并保留用户编辑及撤销历史，不清空后台正文。
- [x] 文件内容加载不进入用户撤销历史、脏状态或正文备份；实际编辑仍使用原有只读开关、撤销、保存和 Hot Exit 流程。
- [x] 底部搜索和高级搜索在后台逐行扫描已编辑正文与未加载的磁盘尾部，复用现有匹配器、结果结构和结果窗口。一次搜索编译全部条件，同一行的大小写转换由条件共用；普通匹配、正则、简化正则、全词和多条件行为保持一致，不使用受限正则子集。
- [x] 搜索期间的用户编辑、底部搜索条件变化和关闭标签使过期任务失效；已加载正文的追加不改变逻辑全文，也不要求重新扫描全文。结果定位通过原有入口补齐所需正文。
- [x] 保存将已编辑正文与未加载尾部完整写入临时文件，再替换目标，避免把当前加载内容当作全文覆盖。保存失败保留原文件；保存后更新继续加载的字节边界。
- [x] 会话正文备份与读取边界同步保存，恢复后继续读取未加载尾部；源文件版本不一致时将未保存正文恢复为独立文档并提示，不拼接未知版本的文件尾部。

读取与搜索分别使用有界后台队列。任务预留 24 MiB，显示正文按字符及段落逐批申请全局额度，同时检查 JVM 堆余量及系统可用内存。额度不足时停止追加并提示，已显示正文和用户修改保留。

当前显示正文采用连续追加，尚未实现可编辑窗口的自动裁剪；搜索结果仍沿用原有完整命中行与结果文档，密集命中和单条超长行的占用尚未有界化。现有结果定位使用 `int` 字符偏移，扫描超过可定位范围时明确报错。内存成本系数和 Windows／macOS 实际吞吐、响应及驻留内存仍需测量，不能宣称已经满足整程序物理内存 10% 的目标。

## 内存预算与初始参数

全程序目标预算 `B = 电脑物理总内存 × 10%`，所有标签、正文、搜索、结果窗口和 Markdown 内容共用，不能每个文件各占 10%。同时监测系统可用内存和 JVM 剩余堆空间；系统压力增大时继续下调缓存。系统内存探测失败时使用受当前 JVM 可用堆约束的保守额度并提示，不能把 `Runtime.totalMemory()` 当物理总内存。

以下是初始规划，均需在 Windows／macOS 实测后调整，不是已验证的内存保证。

### 前置：测量 RichTextFX 追加与换页的内存放大

必须先用项目实际的 RichTextFX 0.11.7、Java 17 和 CodeArea 封装测量，再确定页面大小。追加 1 MiB 源内容不等于增加 1 MiB 内存；解码文本、段落／片段／样式结构、可见节点、撤销历史、搜索快照及临时分配都需计入，同样字节数的短行密集日志和长行日志可能有不同成本。

- [ ] 预热字体、CSS 与布局后记录基线；分别测量追加后的稳定堆增量、追加／替换期间峰值和进程驻留内存。等待布局及后台回填完成，结合受控回收后的保留对象分析，不能仅比较两次未经控制的 `freeMemory()`。
- [ ] 测量 50 MiB 初始加载、后续每次 5 MiB 读取／追加，以及较小 UI 提交批次的成本；对比空文档和已有加载窗口时的追加，同时记录 I/O 缓冲、解码和搜索峰值。覆盖 ASCII、中文、密集短行、超长行、自动换行开／关、无高亮／多条件密集高亮、撤销开／关和搜索结果窗口。
- [ ] 对比追加、整页替换、头部裁剪和关闭标签；连续至少 50 次换页／追加后裁剪，检查当前页相同规模时的保留内存是否趋于稳定，定位旧页、撤销记录、监听、样式缓存或搜索任务仍持有的对象。
- [ ] 记录字符数、段落数、样式片段数、可见节点及每批稳定／峰值增量，建立保守成本模型：`字符成本 × 字符数 + 段落成本 × 行数 + 样式成本 × 片段数 + 视图／任务开销`。系数取实际场景的保守值并留余量，不预设统一的“文本字节数 × 固定倍数”。
- [ ] 页面替换纳入旧页、新页、输入缓冲、布局及后台任务同时存活的峰值；追加前用模型预估，追加后按实际反馈调整。超过额度时缩小后续页、减少预取或裁剪窗口，不等到 OOM 才处理。
- [ ] 分段加载需要区分文件内容加载与用户编辑，加载、换页和裁剪不能进入用户撤销历史或误触发脏状态、全文搜索快照和 session 正文备份；用户编辑保留原有撤销及正文备份语义。

产出：常驻内存与操作峰值的测量表、主要保留对象、页面／批次推荐值及两平台差异。下列页面与缓存参数在测量完成前均为候选上限，实际加载还受模型估算额度约束；64 MiB 显示预算包含文档对象和样式，不是允许加载 64 MiB 原始文本。

| 物理内存 | 整程序目标预算 | JVM 最大堆初始上限 | 日志常驻数据预算 |
|---|---:|---:|---:|
| 4 GiB | 约 410 MiB | 256 MiB | 64 MiB |
| 8 GiB | 约 819 MiB | 512 MiB | 128 MiB |
| 16 GiB | 约 1,638 MiB | 1,024 MiB | 256 MiB |

JVM 堆也包含普通编辑器和应用对象；整程序还包含 JavaFX、线程栈、直接缓冲区及其他原生内存。最大堆必须与启动器／打包 JVM 参数协调，运行后不能仅靠缓存限制改变其启动上限。堆上限不等于进程总内存上限，10% 以实际进程内存为验收目标，保留原生内存和临时分配余量；空闲基线已超预算时需说明并降低功能负载。

8 GiB 电脑的日志常驻数据先按下表分配；各项是可调的初始分配，未用额度可共享，总额受约束。按解码文本、行对象和样式等实际估算占用计费，不能只按源文件字节数计算；50 MiB 初始加载也必须先通过预算检查。

| 项目 | 初始额度／限制 |
|---|---|
| 页面缓存 | 合计 24 MiB，所有标签共用 LRU |
| 当前显示文档及样式 | 合计 64 MiB，非活动日志释放显示对象、保留位置 |
| 搜索结果内存页 | 合计 16 MiB，其余结果索引落临时文件 |
| 稀疏索引缓存 | 合计 8 MiB，完整索引落盘 |
| 读取、解码和任务队列 | 当前读取／扫描任务各预留 24 MiB、结果页任务预留 8 MiB；复用读取缓冲，有界队列，禁止积压全文片段 |
| 单次 I/O | 默认最多 5 MiB 源字节；处理实际读到的长度，解码器保留跨块字符状态 |
| 每个 Tab 初始加载 | 目标 50 MiB 源内容，文件不足则读到末尾；按 10 次 5 MiB 分批完成，额度不足时缩小实际加载量 |
| 后续加载 | 每次目标 5 MiB，追加前重新申请全局额度；必要时回收旧窗口，再按需读回历史内容 |
| 单次 UI 提交 | 当前按最多 250,000 个 UTF-16 字符分批布局；密集短行需实测后增加行数或耗时限制；不作为整个 Tab 的加载上限 |
| 首屏与预取 | 首屏优先显示，后台继续完成 50 MiB 初始窗口；预取按剩余额度申请，避免初始加载前后再无条件读取 |
| 结果展示 | 每页 200 条，内存最多 2,000 条摘要且受 16 MiB 总额约束；每条摘要最多 512 字符 |
| 重后台任务 | 全局先限制为 1 个全文扫描，显示页加载优先 |

50 MiB 是每个 Tab 初始加载窗口的目标，5 MiB 是单次磁盘读取及后续加载的目标批次，UI 再按小批提交。初始 50 MiB 无需同时创建 50 MiB 原始缓冲，但已解码并保留的内容、段落和样式全部计入该 Tab 占用。全局协调读取缓冲的复用，避免扫描、索引和预取同时持有多份 5 MiB 缓冲；8 GiB 电脑日志常驻数据初始总预算仍为 128 MiB，实际可加载多少源内容由测量结果决定。

文件类型决定读取方式：仅 `.txt`、`.log` 使用分段读取；Markdown 和其他文本完整读取，不按大小或行数自动转换为日志模式。普通编辑器的全文内存及多标签预算仍需纳入后续测量。

进程占用接近预算的 80% 时回收冷缓存、停止预取；达到 90% 时收缩显示页、限制新任务；预计超预算时不再启动分配较大的操作。若 JVM 可用堆更少，提前触发。关闭文件、结果窗口或取消任务后及时释放对象、句柄及临时数据，不依靠反复强制 GC 维持预算。

### 多 Tab 共用预算

- [ ] 建立全局预算管理器，记录每个 Tab 的已加载源范围、估算常驻占用、显示对象／样式、独占缓存、结果及待完成任务预留。共享文件块和索引只计费一次；普通编辑与 Markdown Tab 的实际占用也影响余量。
- [ ] 预算账本按 `全局余量 = 总额度 - 应用基线 - 各 Tab 常驻占用之和 - 共享占用 - 安全余量 - 在途任务预留` 计算，再受当前进程、JVM 堆和日志数据额度限制；实测进程占用与账本是校验关系，不能重复相加扣费。
- [ ] 初始 50 MiB、后续 5 MiB、预取、搜索和结果生成均先申请峰值额度再执行；多 Tab 并发申请统一协调，避免各自看到相同余量后超额加载。完成或取消任务时更新常驻账目并释放未使用的预留。
- [ ] 当前活动 Tab 优先，正在对照的可见 Tab 次之，后台 Tab 停止预取并优先释放冷缓存／显示文档；后台仅保留路径、位置、过滤和书签等状态，激活后按剩余额度恢复。批量打开或启动恢复时不同时为所有 Tab 读入 50 MiB。
- [ ] 额度不足时先回收可重建的后台数据，再缩小新 Tab 的加载窗口或追加量；界面明确显示实际已加载范围和预算限制，不能显示为已加载 50 MiB。普通编辑器未保存内容与必要撤销记录不得作为可丢弃缓存。
- [ ] 切换、关闭 Tab、调整搜索条件及文件轮转后重新分配额度；预算模型随实测反馈校准，不能仅按“已加载 MB”或简单平均分给各 Tab。

## 第一批：分段加载与全文件搜索

- [ ] 完成 RichTextFX 追加／换页内存测量，按实际字符、段落和样式成本校准预算及批次大小，作为分段加载的前置验收。
- [ ] 完成多 Tab 预算账本、峰值预留、活动 Tab 优先及后台回收；每个 Tab 的初始／追加量受其他 Tab 占用后的余量约束。
- [ ] 设计可编辑的文件分段后端：初始目标加载 50 MiB，后续每批 5 MiB；内存只保留预算允许的有限窗口及缓存，翻页时替换或裁剪，不能持续向同一个 CodeArea 追加全部文件。分段编辑、撤销、保存和会话恢复必须一起设计，不得按扩展名强制只读。Markdown 等其他文本继续完整读取并使用现有编辑能力。
- [ ] 首屏立即可读，后续加载及定位复用现有编辑器交互，不增加日志专用工具栏或改变底部原有逻辑。全文行数未知时不伪造精确滚动比例。
- [ ] 后台构建稀疏行索引，初始每 4,096 行保存行号与文件字节偏移；按最近检查点扫描到目标行，索引未完成时允许等待或取消，不要求首屏前完成全文件索引。
- [ ] 文件大小、字节偏移、全局行号和匹配计数使用 `long`；CodeArea 的 `int` 偏移仅用于当前页，结果以文件身份、版本、全局位置和页内列定位，支持超过 2 GiB 的文件。
- [ ] 分块解码支持现有常用编码，处理 BOM、UTF-8／GBK 多字节字符、UTF-16 对齐、CRLF 跨块及文件末尾无换行；编码切换废弃原索引和缓存。解码错误有明确提示。
- [ ] 超长单行按有限窗口展示，保持同一个真实行号；搜索普通文字时跨窗口匹配，不能无限积累完整单行，也不能把截断内容当作已完整搜索。
- [ ] 搜索明确区分“当前页”和“整个文件”，默认日志全文搜索从磁盘分块扫描；复用多条件、大小写、全词及单行正则语义，一次扫描处理已启用条件，边读边返回结果和进度。
- [ ] 跨块同一行、字符边界和全词边界不漏匹配、不重复计数；正则默认逐日志行匹配，跨行正则后置。超长行正则的支持上限必须明确，不能静默跳过；未覆盖范围单独提示。
- [ ] 搜索支持实际可生效的取消、错误和耗时控制，参数变化及文件关闭使旧结果失效。不能仅靠 `Future.cancel()` 承诺终止 Java 回溯正则；实施时确定受限规则或可终止隔离方案，隔离进程也计入整程序预算。
- [ ] 结果只保留有限摘要，完整命中索引落盘并分页；命中位置与上下文按需加载，底部上一个／下一个也不要求全部命中常驻内存。命中行数与匹配次数分开统计，扫描结束前标明已发现数量；临时文件达到磁盘额度或写入失败时暂停并提示，不能把不完整结果显示成已全部完成。
- [ ] 只对当前显示页及结果页着色，不为整篇构造样式。保留高级搜索配置和结果联动，并为跨页选区、复制及筛选结果导出提供流式读取；超大剪贴板操作设上限，允许改为导出。
- [ ] 文件追加、截断、替换和删除使缓存／搜索有明确版本边界。首批全文搜索固定开始时的文件长度，追加内容另行提示；覆盖或截断时废弃过期结果。
- [ ] 分段编辑使用完整文件事务保存，禁止把当前页当全文写回；会话必须保留未保存修改及阅读位置，避免恢复时丢失编辑或重复整篇读入。

验收：100 MiB、1 GiB、10 GiB 日志，以及大量短行、单行超过 10 MiB、中文／不同编码、全文件高频命中的场景中，加载、搜索、结果和索引内存均有界；取消与关闭能释放资源。连续换页／追尾裁剪后的保留内存趋于稳定，换页瞬时峰值也计入预算。覆盖 1／5／10 个日志 Tab、混合 Markdown／未保存编辑 Tab、快速切换、批量恢复和多个加载请求，验证其他 Tab 占用会减少可申请额度，关闭后可重新分配。记录首屏耗时、扫描速度、峰值进程内存和 UI 响应，8 GiB 机器以整程序约 819 MiB 为目标。

## 第二批：日常日志排查能力

- [ ] 实时追尾：追加检测、跟随文件尾、暂停／继续、新增行计数；用户回看时停止自动跳底。处理末尾半行、截断和日志轮转，历史仍从磁盘按需读取。
- [ ] 多条件包含／排除、AND／OR、级别、时间区间、线程／标签过滤；继续支持分色方案，筛选视图保留原文件行号和上下文，规则变化可取消重算。
- [ ] 命中上下文、书签、导航历史、请求 ID／线程链路追踪、两处日志对照；堆栈多行在展示与过滤中尽量作为一个事件，不丢异常上下文。
- [ ] 工作区／目录跨文件流式搜索，文件类型、时间和数量范围可限制，支持轮转日志；沿用全局任务与内存预算，不要求先打开所有文件。
- [ ] 时间、级别、线程、标签字段提供可配置解析规则和纯文本回退；支持复制原文、格式化查看日志内 JSON，展示格式不改变原文件。
- [ ] 按级别／关键字／时间段统计，支持提取上下文或筛选结果到文件／新标签；导出流式写入，不拼接完整结果字符串。
- [ ] 搜索和过滤方案导入／导出，保存文件位置、过滤条件及书签；大日志处理状态可恢复，索引失效或临时文件过期能重建。

验收：打开日志、配置过滤／分色、查看命中上下文、回看追尾和导出片段能够连贯完成；追加与轮转不误定位，不因长期追尾或高命中率持续增长内存。

## 第三批：专项复杂能力，逐项确认

开始每项前确认日志来源、实际用途、支持范围和成本。前两批的内存、定位与取消问题不能延期到本批。

- [ ] 多文件按时间合并、跨时区／时钟偏差校正及跨进程链路关联。
- [ ] 复杂跨行正则、事件级查询语言及高级字段索引加速。
- [ ] 压缩／归档日志、远程日志与设备实时采集，具体格式或来源分别确认。
- [ ] 时间线、耗时分布、异常聚合等可视化分析及报告输出。
- [ ] 大文件直接修改、流式替换和安全保存，另行设计文件事务与恢复，禁止直接复用普通全文编辑保存流程。

## 实施入口与约束

- 文件打开：`AllEditorsManager`、`EncodingUtil`、`StaticsProf`。
- 搜索与结果：`BottomHandler`、`FinderRegexImpl`、`OneFileSearchResults`、`ResultItem`、`AbstractResultUpdater`。
- 会话与文件变化：`EditorSessionManager`、`EditorAreaMgr`。
- 新增日志数据源、预算管理和流式搜索接口，UI 仅消费当前页；所有后台任务和回填校验文件版本与请求编号。
- Windows／macOS 同时支持；新代码优先 Kotlin，索引／结果缓存有磁盘额度与退出／过期清理策略。

## 技术依据

- [Java 17 系统内存接口](https://docs.oracle.com/en/java/javase/17/docs/api/jdk.management/com/sun/management/OperatingSystemMXBean.html)：物理总内存与系统可用内存用于预算，不能把 JVM 内存误当电脑内存。
- [Java 17 Runtime](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/lang/Runtime.html)：`maxMemory()` 等描述 JVM 内存，需配合进程内存观测。
- [CharsetDecoder](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/nio/charset/CharsetDecoder.html)：分块解码保留状态并处理块边界。
- [RichTextFX 0.11.7 编辑器实现](https://github.com/FXMisc/RichTextFX/blob/v0.11.7/richtextfx/src/main/java/org/fxmisc/richtext/GenericStyledArea.java)、[文档模型](https://github.com/FXMisc/RichTextFX/blob/v0.11.7/richtextfx/src/main/java/org/fxmisc/richtext/model/ReadOnlyStyledDocument.java)：文档数据、虚拟化视图和撤销管理需要分别计入。
- [MemoryMXBean](https://docs.oracle.com/en/java/javase/17/docs/api/java.management/java/lang/management/MemoryMXBean.html)：记录堆使用情况，结合对象分析和进程内存观测区分保留成本与操作峰值。
