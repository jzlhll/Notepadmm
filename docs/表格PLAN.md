# Markdown 表格直接编辑与操作工具栏

## 一、目标与交互

- 表格默认采用可直接编辑的表格形态；鼠标、光标和选区变化均保持当前形态。
- 每张表格独立提供「显示源码／显示表格」，仅点击按钮时切换。
- 活动单元格显示 Markdown 标记，其余单元格显示渲染结果；编辑时保持表格边框及列宽稳定。
- 文件使用 Markdown，保存、修改状态、会话恢复及撤销重做统一由主文档管理。
- 本期包含已有单元格编辑、末尾增行增列、右键删除行列；不包含合并单元格、拖动列宽、矩形多选和批量粘贴为多格。

## 二、首个实施阶段：模型保持与形态状态

这一阶段完成后，实施单元格编辑及工具栏功能。

### 状态宿主

- 每个 `EditorArea` 持有一个 `MarkdownTableDocumentState`，记录表格稳定标识、形态、源码范围、行列映射和水平滚动位置。
- 状态生命周期与 `EditorArea` 一致，负责跟踪文档文本差量；视图管理器的绑定、解绑仅处理界面和监听订阅。
- 表格形态由 `MarkdownTablePreviewManager` 承载，沿用段落图形装饰、行虚拟化、段落行高撑开及源码隐藏机制，创建单元格展示节点并定位独立编辑覆盖层。
- 呈现形态仅取自 `MarkdownTableDocumentState`；光标和选区事件用于编辑定位、选择提示及工具栏显示。解绑释放界面资源与订阅，文档模型和形态状态由 `EditorArea` 持有。
- 切换标签、视图重新绑定及普通重解析保留状态；关闭文档释放状态，整文档外部重载按默认表格形态建立状态。
- 单元格输入、增删及优化操作携带目标表格标识，明确更新该表格及其后续范围。

### 范围更新与解析回填

- 使用主文档字符偏移作为范围依据，文本差量先同步更新表格、行和单元格偏移，行号作为派生信息。
- 表格前方插入或删除文本仅平移范围；已知单元格编辑即时更新目标单元格、所在行及后续范围。
- 保留后台防抖解析与文档版本校验，解析完成后更新已有模型及受影响视图。
- 普通源码编辑后，按经过差量修正的源码范围匹配：优先起始锚点一致，其次采用唯一的一对一范围重叠。表格拆分、合并或匹配不唯一时建立新标识，默认表格形态。
- 单张表格源码暂时失效时，保留其源码模式及差量跟踪范围；在该范围恢复合法表格后沿用标识和形态。
- 文本变更期间，未受影响的表格模型、段落呈现及测量缓存保持有效；有效的格内输入期间，活动表格持续显示。
- 仅文件解绑、销毁、整文档重载或大文档限制等整体生命周期事件执行整体验证及清理。

## 三、直接编辑与文档同步

- 使用一个可复用的多行编辑控件覆盖活动单元格，控件位于编辑区独立覆盖层，生命周期独立于虚拟化行节点。
- 单击按点击位置放置光标；控件随单元格移动并按视口裁剪。滚出视口保留编辑状态，恢复可见时继续使用同一控件。
- Tab／Shift+Tab 移动到相邻单元格；越过首尾单元格返回表格前后正文，不自动增行。文档边界在实际输入正文时补充必要换行。
- Enter 和粘贴换行形成格内换行，序列化为 `<br>`；制表符作为当前单元格内容处理。
- 保留行内 Markdown 语法，竖线按 GFM 规则转义，已有转义避免重复编码。未修改单元格的源码保持原样。
- 已提交输入立即以最小文本差量写入主文档，并同步更新模型；回填过程使用重入保护，避免重复写入。
- 中文组合输入期间保持控件及选择稳定，仅已提交文本进入主文档；切换单元格、形态及结构操作等待组合输入完成。
- 撤销重做统一调用主文档并回填活动单元格；单元格控件不使用独立撤销链。切换单元格及结构操作设置撤销合并边界。
- 撤销重做及结构操作执行前，等待组合输入结束并同步已提交输入；执行后按文本差量修正活动单元格定位。显式增删按增删规则选择目标单元格，其余情况仅在活动单元格仍有效时回填。
- 活动单元格无法对应且操作没有有效目标时，结束格内编辑，以差量修正后的单元格起始偏移定位主编辑器光标，偏移限制在文档有效范围内；落点位于表格形态的隐藏源码内时，定位到该表格之后的正文边界。退出过程仅释放编辑状态，文档内容以撤销重做或结构操作结果为准。
- 格内复制、粘贴、全选及格式快捷键作用于活动单元格；保存作用于主文档。父编辑器事件按实际焦点分发，避免修改隐藏源码。

### 选择与搜索

- 格内鼠标拖拽仅选择当前单元格文本。
- 从正文开始拖拽遇到表格形态时，选区止于表格边界；跨表格鼠标拖拽选择不属于本期能力。
- 正文焦点下，Shift 加方向键可以扩展主文档选区并穿越表格；表格保持形态，对与选区相交的单元格显示选择提示，复制使用原始 Markdown。
- 活动单元格内的 Shift 选择仅作用于格内文本。
- 搜索命中单元格内容时定位并选择对应格内文本；命中分隔行或结构标记时高亮所属表格。源码形态沿用主编辑器选择行为。

## 四、工具栏、操作与布局

### 工具栏

表头上方提供「增加一行」「增加一列」「优化表格」「显示源码／显示表格」。

- 鼠标位于表格、工具栏或所属菜单内，或者编辑焦点位于表格内时显示；其余情况隐藏。
- 同时满足条件时，鼠标所属表格优先于编辑焦点所属表格；界面仅显示一套工具栏。
- 工具栏不占正文高度，限制在编辑区内；表头滚出视口而表格仍可见时，停靠在编辑区顶部。
- 两种形态均提供工具栏；操作保持当前形态。

### 增删与禁用状态

- 增行在末尾追加空数据行，聚焦首格；增列在最右侧补齐表头、分隔行及数据行，采用默认左对齐并聚焦新列表头。
- 源码形态新增后定位到对应源码位置。
- 表格形态右键菜单提供「删除当前行」「删除当前列」，目标由右键单元格确定。
- 格内右键菜单同时提供「撤销」「重做」「剪切」「复制」「粘贴」「全选」，文本操作作用于右键所在单元格，撤销重做调用主文档。右键活动单元格保留已有选区；右键其他单元格时先激活目标单元格并按点击位置定位，再显示菜单。
- 菜单项按选区、剪贴板、撤销重做可用性及只读状态启用；只读时允许复制和全选，剪切、粘贴、撤销重做及删除操作置灰。
- 表头禁止删除行；仅一列时禁止删除列；允许删除全部数据行。
- 删除后保持原行列位置，越界时选择前一个有效位置。
- 每次增删及优化作为一次独立撤销操作。
- 只读状态允许选择、复制和形态切换，编辑及修改按钮置灰。
- 源码暂时无效时保持源码可编辑，增删、优化及「显示表格」置灰，提示原因；恢复合法结构后启用。

### 源码优化

- `MarkdownTableOptimizeManager` 提供同步纯字符串格式化入口，支持单列表格，不依赖 JavaFX 节点和字体。
- 列宽按去除外围空白后的源码计算，采用固定的 Unicode 显示列宽规则：非间距组合标记、变体选择符及零宽连接符优先计 0 列；其余字符按 East Asian Width 分类，W／F 计 2 列，A／H／Na／N 计 1 列。根据显示列宽及对齐标记补空格，分隔行至少三个连字符，并保留换行风格及容器前缀。
- 源码优化以逻辑显示列对齐为目标；实际字形宽度由字体和排版决定，任意字体及组合 emoji 的像素级对齐不属于保证范围。
- 相同输入得到相同输出，重复优化幂等；内容和 Markdown 对齐语义保持一致。
- 工具栏首次显示或目标源码变化时，同步格式化并与原文比较；相同则「优化表格」置灰，不同则可点击。
- 只读、源码无效或无法安全映射时置灰；按钮始终保留，悬停显示原因。
- 鼠标移动、滚动及字体变化仅影响界面定位或布局，不触发优化判断。优化不设置后台任务、字体缓存或计算中状态。

### 表格布局与横向滚动

- 表格最大可视宽度取 editor 扣除左右 padding、行号区域后的正文宽度，按像素向下取整。
- 自然列宽取表头和全部数据行中最长渲染行的宽度，忽略 Markdown 标记，显式换行按最长一行计算。
- 长列最低内容宽度为当前表格字体、editor 字号下 40 个英文等宽字符的实测宽度；40 字符是可读下限，不是固定宽度或宽度上限。
- 自然内容宽度不超过该值的短列按内容加留白定宽；序号、状态、类型不根据列名特殊识别。空列保留一个英文字符及留白的宽度。
- 全短列的表格按自然宽度紧凑、左对齐；存在长列且最低宽度总和能够容纳时，表格展开到正文宽度，短列保持定宽，长列均分剩余空间。
- 长列达到自然宽度后先停止扩展，将空间留给仍需换行的长列；全部长列达到自然宽度后，额外空间只在长列间均分。因此两三列表格中的长说明可以充分展开，序号列不会被拉宽。
- 只有最低宽度之和超过正文宽度时才启用表格内部横向滚动，各列采用最低宽度；不设置固定列数阈值。统一列宽取整和尾差分配，避免边界处产生多余滚动条。
- 最终列宽确定后测量换行高度；中文、英文、行内代码及无空格长路径均在列内断行，保留 `<br>` 显式换行。视觉换行不写回 Markdown。
- 内容区统一扣除左右各 13px、上下各 10px，包含单次绘制的边框与留白。行高取该行所有单元格的最大需要高度，背景、边框、裁剪和隐藏源码段落同步更新。
- 活动格按输入框中的原始文本、字体和实际内容宽度测量，包括 Markdown 标记；其他格使用预览高度。输入期间固定列宽，只更新活动格及所在行，不重新挂载编辑框。
- 同一表格内切换单元格不重新分列，离开表格后合并执行列宽重算；窗口或字号变化触发完整布局更新。颜色主题变化不清除尺寸缓存。
- 点击进入编辑后，使用实际横纵坐标和 TextAreaSkin 的字符命中接口定位光标；键盘切换分别定位到单元格首尾。
- 每张表格共享水平偏移；超宽时在最后一行下方显示 12px 水平滚动条，正文行高与滚动条占位独立维护。扩宽后能够容纳时清零偏移并移除滚动条。
- 表格、活动格内的横向手势及 Shift＋纵向滚轮同步更新各行位移和滑块，消费事件；普通纵向滚动交给正文。正文水平滚动独立，源码形态沿用常规滚动。

### 解析、缓存与增量呈现

- 表格行内解析与全文 Markdown AST 缓存隔离，在已有后台刷新任务中生成不可变行内展示数据；重复源码复用展示数据。
- 每个单元格仅保留当前源码、字体、自然宽度、当前列宽下的高度。源码变化使对应单元格失效，字号变化使尺寸失效；删除表格、解绑和销毁时释放缓存。
- 列宽分配及 JavaFX 测量在 FX 线程分帧执行，每帧约 4ms 协作预算，在单元格之间检查，不逐格创建异步任务。共享测量 TextFlow 和 Text 节点，不为离屏单元格长期保存控件。
- 每张表完成全部测量后统一应用，重测期间保留旧布局；首次结果就绪前保留源码。后台结果校验文档版本，分帧任务同时校验文档和布局版本，过期结果丢弃。
- 使用行号索引和行序号定位单元格；布局稳定后的滚动不重新解析或测量，只为新进入视口的行创建显示节点。
- 内容、尺寸和选中样式分别刷新；高度未变不重建图形，选择变化直接更新可见节点样式，横向滚动只更新位移和滑块。
- 单格输入只重测该格，其他格使用缓存；后台回填复用未变化单元格的测量结果。正文编辑不重测内容未变化的表格。
- 窗口尺寸变化合并到每帧一次，仅实际列宽变化的列重测高度。不使用抽样列宽或估算行高，继续遵守现有大文档实时处理限制。

## 五、人工验收

人工验收场景：

- 连续格内输入期间，活动控件保持同一实例，表格持续显示，其他表格不清空重建。
- 表格前方增删多行、表内增删、切换标签及重解析后，形态和目标定位正确。
- 中文组合输入、Markdown 标记、换行、竖线及转义内容，保存重开结果一致。
- 增删、单列表格、空数据区、表头、只读和无效源码边界符合约定；结构操作可一次撤销恢复。
- 新增行或列并聚焦后立即撤销，以及撤销重做导致活动单元格或整张表格消失时，编辑状态正确结束、正文光标落点有效，文档内容保持操作结果。
- 右键活动单元格保留选区，右键其他单元格作用于目标格；复制、粘贴、全选及菜单撤销重做可用，只读和空选区等禁用状态正确。
- 优化结果幂等，已优化时置灰；改变字体不影响优化输出和可用性。
- 源码优化中的中英文混排、全角标点及组合字符采用约定的 Unicode 显示列宽规则；预览布局使用 JavaFX 的实际字体测量。
- 正文鼠标选区止于表格边界；键盘 Shift 选区可穿越表格，复制得到对应 Markdown。
- 表格横向手势与独立滚动条同步移动各行，普通纵向滚动作用于正文，正文水平位置不受表格手势影响。
- 搜索、保存、撤销重做、外部重载及大文档限制场景内容完整。

补充布局与性能验收：

- 序号＋长说明、序号＋两列长说明、两列长文本、全短列及多长列；检查最低宽度总和小于、等于、大于正文宽度的边界。
- 长路径、无空格代码、显式换行、空列、仅表头、编辑第二行及以后文本、删除至空和调整字号；不得裁切文字或出现行高不一致。
- 在现有大文档限制内采样 100 行和 1,000 行的短值、重复内容及长文本；分别记录首次测量、缓存命中和重排耗时及节点数量。
- 确认滚动和选择不触发测量、单格输入不重建活动编辑框、未变化表格复用测量缓存，重复滚动后缓存不持续增长。4ms 是分帧调度预算，不作为未经实测的帧率保证。

不新增自动化测试，不主动运行 Gradle。
