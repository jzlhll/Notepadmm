# 微信输入法中文标点兼容性

适用范围：macOS、JavaFX 27；已确认运行版本为 `27+30`。

## 原因与验证结果

微信输入法在没有组合文本时直接提交单个中文标点，Glass 原有路径却使用原始 `NSEvent` 字符：微信提交 `。`／`，`，应用收到 `.`／`,`。

[JavaFX 27 原生实现](https://github.com/openjdk/jfx/blob/27-ga/modules/javafx.graphics/src/main/native-glass/mac/GlassView3D.m#L383) 只对 Keyman 启用单字符覆盖；JDK-8356652 的专项适配未覆盖微信输入法。

本地日志已确认微信输入源 `com.tencent.inputmethod.wetype.pinyin` 的上述行为：补丁成功转发 5 次中文逗号／句号，英文标点提交未被干预，实际输入效果正常。本次没有桥接错误；其他标点、候选交互、快捷键及其他输入法仍需覆盖验证。

## 当前解法

[`MacInputMethodPunctuation.kt`](../src/main/java/com/allan/atools/toolsstartup/MacInputMethodPunctuation.kt) 在应用启动后，通过 JNA 安装两个进程内原生拦截点：

1. 从 `insertText:replacementRange:` 捕获无组合文本的单字符中文标点。
2. 匹配同一 Glass delegate、原生事件及时间戳，在 `sendJavaKeyEvent:isDown:character:` 中用实际提交字符替换原始字符。

原方法各调用一次，保留物理键、修饰键及消费结果；已有字符覆盖、Cmd/Ctrl 快捷键、英文标点与组合提交沿用原逻辑，不改写组合状态或重复插入。

补丁默认启用，仅支持 macOS 的 64 位 JavaFX 27；安装前校验原生方法签名及字段类型，不兼容或发生桥接错误时停止修复并记录错误。升级 JavaFX 后需重新核对原生实现。使用微信输入法时关闭底部“中文标点”补偿，由输入法控制中英文标点；可用 JVM 参数 `-Datools.macos.imePunctuation=false` 停用补丁。

## 日志定位

日志位置及查看方式见根目录 [`AGENTS.md`](../AGENTS.md) 的“日志查看”，筛选 `macOS IME:`：

- `hooks installed`：拦截点安装成功。
- `insert`：输入源、提交／原始码点、组合状态及修复条件。
- `key down` 中 `matched=true, repaired=true`：实际提交字符已转发，例如 `raw=U+002E, forwarded=U+3002` 表示 `.` → `。`。
- `bridge unavailable`、`hook installation failed` 或其他失败日志：补丁未启用或已停止修复。

诊断最多记录 200 条，不记录普通正文；日志命中仅证明字符转发，最终效果以编辑器实际内容为准。
