# 微信输入法中文标点兼容性调查

检索日期：2026-10-08。

## 结论

其他软件存在与 ATools 类似的中文标点兼容问题，且有公开报告明确涉及微信输入法。已找到的直接案例主要发生在 macOS：第三方输入法输入中文时，标点仍输出为英文，而系统自带输入法正常。

这些案例能够确认类似现象存在，但尚不能证明 ATools 与其他软件具有相同根因，也不能据此确定问题属于微信输入法、JavaFX、RichTextFX 或 ATools 自身的事件处理。

## 公开案例

| 软件 | 报告环境与现象 | 证据范围与状态 |
| --- | --- | --- |
| Tabby 终端 | macOS 26.0、Tabby 1.0.230 arm64；微信／搜狗输入法输入中文句号、逗号、书名号时得到英文标点；报告者称同一输入法在 iTerm2 和系统终端正常。 | 明确涉及微信输入法，与当前现象最接近。2026-02-04 提交，检索时仍为 Open。[Issue #11013](https://github.com/Eugeny/tabby/issues/11013) |
| VS Code 内置终端、Neovide 编辑器 | macOS 15.2；fcitx5-macos 的小鹤双拼和全拼均无法输入中文句号、书名号等全角标点，系统自带输入法正常。 | 涉及 fcitx5，并非微信输入法；检索时已关闭，带有 `objectively won't do` 标签，不能将关闭理解为已修复。[Issue #223](https://github.com/fcitx/fcitx5-macos/issues/223) |
| Neovide 编辑器 | 鼠须管在其他软件输入全角符号正常；在 Neovide 中单独按逗号得到半角逗号，但拼音候选尚未提交时按逗号，可以得到全角逗号。 | 涉及鼠须管；说明直接输入标点与随候选词提交标点可能经过不同处理路径。2023-12-29 提交，检索时已关闭，已读取内容未确认修复方案。[Issue #827](https://github.com/rime/squirrel/issues/827) |

以上现象来自问题报告，未在本地逐一复现。VS Code 案例针对内置终端，不能外推到整个代码编辑区。

Tabby 报告者提出过键盘事件处理与输入法提交文本不一致的猜测，但这不是已确认的根因。关于系统输入法是否具有特殊权限，也没有足够证据作出结论。

## JavaFX 的相关底层案例

OpenJFX 的 JDK-8356652（`Input field ignores custom input source characters`）针对 Keyman 第三方输入法提供过适配：

- Keyman 在底层表现为美国英语键盘布局，原始 `NSEvent` 携带的仍然可能是英文字符。
- 正确的输入字符通过 macOS 的 `insertText:replacementRange:` 提交。
- 修复针对 Keyman 检测输入源，并在 Glass 原生层记录提交字符，用于生成 JavaFX 按键事件。

来源：[OpenJFX 开发者讨论](https://www.mail-archive.com/openjfx-dev%40openjdk.org/msg19915.html)、[对应 PR #1805](https://github.com/openjdk/jfx/pull/1805)。该问题列于 [JavaFX 25 官方发布说明](https://docs.oracle.com/en/java/java-components/javafx/25/release-notes/javafx-release-notes.pdf)。

这个案例证明原始按键字符与输入法最终提交字符可能不同，但适配对象是 Keyman，不能认定其已经修复微信输入法，也不能直接套用其根因。

## ATools 当前处理及限制

当前实现位于 [`EditorArea.kt`](../src/main/java/com/allan/atools/richtext/codearea/EditorArea.kt)，涉及 `FULLWIDTH_PUNCTUATION` 和 `KeyEvent.KEY_TYPED` 过滤器。

当当前标签页开启“中文标点”、编辑器可编辑且不处于输入法组合阶段时，过滤器会将收到的单个半角标点替换为映射中的中文标点。

这一设置属于输出补偿：

- 能将已经收到的英文标点转换为中文标点。
- 没有识别微信输入法当前的中英文输入状态及中英文标点状态，因此无法自动跟随输入法状态切换。
- 没有解决输入法原本提交的中文标点为何未正确到达编辑器的问题。

仅凭现有实现与公开报告，尚不能确定字符在哪一层发生丢失、替换或提前处理。

## 后续定位方向

优先对照 JavaFX 原生 `TextArea`、纯 RichTextFX `CodeArea` 与 ATools 当前编辑器，使用同一系统环境和微信输入法版本，关闭 ATools 的中文标点补偿后比较：

1. 系统自带输入法与微信输入法的表现。
2. 候选已提交后单独按标点，与拼音候选期间按标点的表现。
3. `KEY_PRESSED`、`KEY_TYPED`、`INPUT_METHOD_TEXT_CHANGED` 接收到的字符、组合文本及提交文本。

如果原生 `TextArea` 同样异常，应优先检查 JavaFX 的 macOS 输入桥接；如果只有纯 `CodeArea` 异常，应进一步检查 RichTextFX；如果只有 ATools 异常，应优先检查自身的事件过滤、快捷键和 Markdown 编辑处理。必要时再对照 Glass 原生层的 `NSEvent` 与 `insertText:replacementRange:` 内容，以确定是否需要原生层适配。
