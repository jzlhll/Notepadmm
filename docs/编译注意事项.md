# 编译注意事项

本文只记录新增三方库或项目模块时容易遗漏的构建联动。常规编译和运行由 Gradle 处理，不需要手动维护 module-path 或复制依赖。

## 新增三方库

- 在实际使用该依赖的模块 `build.gradle` 中声明依赖；只有需要向下游模块暴露时才使用 `api`，其他情况使用 `implementation`。
- JPMS 模块需要在对应的 `module-info.java` 中增加 `requires`。如果新增 JavaFX 模块，还要同步更新该模块 `build.gradle` 中的 `javafx.modules`。
- 普通依赖会由 `runtimeClasspath` 自动进入打包目录，JDK 运行时模块也会由 `jdeps` 自动分析，无需手动修改 jpackage 参数。
- 依赖通过反射访问项目代码时，按需在 `module-info.java` 增加定向 `opens`；依赖访问 JDK 或 JavaFX 内部包时，才在 `gradle.properties` 的 `packageVmOptions` 中补充 `--add-opens` 或 `--add-exports`。
- 依赖依靠反射、资源名称或类名加载代码时，检查 `proguard.pro` 是否需要增加保留规则。

## 新增项目模块

- 在 `settings.gradle` 中注册模块，并为模块创建 `build.gradle` 和 `module-info.java`。
- 在使用方 `build.gradle` 增加 `project(...)` 依赖，同时在 `module-info.java` 增加对应的 `requires`；跨模块使用的包按需声明 `exports`，反射访问的包按需声明 `opens`。
- 当前打包流程在 `gradle/packaging-tasks.gradle` 的 `projectJars` 中显式列出项目模块。新增模块参与发行包时，需要把它的 JAR 加入该列表。
- 新模块只有在访问 JDK 或 JavaFX 内部 API 时才需要调整 `packageVmOptions`，不要为常规模块重复添加 VM 参数。
