# 编译注意事项

开发与打包统一使用 JDK 25、JavaFX 27、Kotlin 2.4.20 和 Gradle 9.6.1。依赖和插件版本集中在 `gradle/libs.versions.toml`；Java 与 Kotlin 均生成 JVM 25 字节码。

在 `local.properties` 配置 `buildJdk.home`，供 `gradlew`、`gradlew.bat`、`macOSBuild.sh` 和 `windowsBuild.sh` 启动使用；目标架构的打包 JDK 通过 `packageJdk.*` 独立配置，必须为对应平台的 JDK 25。路径使用正斜杠、不加引号，遵循示例中的 `key=value` 格式。IDE 的 Project SDK 和 Gradle JVM 需选择同一个本机 JDK 25。Wrapper 脚本含本地 JDK 选择逻辑，重新生成 Wrapper 时需保留该逻辑。

JavaFX 原生访问权限由 `packageVmOptions` 统一配置。JDK 25 的开发编译与运行通过 `--upgrade-module-path` 使用 JavaFX 提供的 `jdk.jsobject`；发行运行时在 `jlink` 时优先链接该模块。Java 编译使用 JDK 25 toolchain 配合 source/target 25，避免 `--release` 与升级模块路径冲突。

本文记录新增三方库或项目模块时容易遗漏的构建联动。常规编译和运行由 Gradle 处理，不需要手动维护 module-path 或复制依赖。

## 新增三方库

- 先在 `gradle/libs.versions.toml` 声明版本与坐标，再在实际使用该依赖的模块 `build.gradle` 中声明依赖；只有需要向下游模块暴露时才使用 `api`，其他情况使用 `implementation`。
- JPMS 模块需要在对应的 `module-info.java` 中增加 `requires`。如果新增 JavaFX 模块，还要同步更新该模块 `build.gradle` 中的 `javafx.modules`。
- 普通依赖会由 `runtimeClasspath` 自动进入打包目录，JDK 静态依赖由 `jdeps` 分析。安全服务等动态提供者需在 `analyzeJreModules` 中显式保留；打包保留 `jdk.crypto.ec` 兼容模块。JDK 25 已将 SunEC 实现移入 `java.base`。
- 依赖通过反射访问项目代码时，按需在 `module-info.java` 增加定向 `opens`；依赖访问 JDK 或 JavaFX 内部包时，才在 `gradle.properties` 的 `packageVmOptions` 中补充 `--add-opens` 或 `--add-exports`。
- 依赖依靠反射、资源名称或类名加载代码时，检查 `proguard.pro` 是否需要增加保留规则。

## 更新打包运行时

`fastCopy.sh` 只同步项目 JAR 和资源，不更新安装包内的 Java 运行时、第三方 JAR 和启动参数。运行时版本或模块清单变化时，该脚本会拒绝复制；升级 JDK、JavaFX 或第三方库后需完整重新打包并安装。JavaFX 27 在 macOS 默认使用 Metal 渲染，应在实际安装包中验收编辑器、WebView、弹窗和中文输入。Windows ARM64 没有官方 Maven 原生包，需要另备 JDK 25 及同版本 JavaFX 27 ARM64 jmods。

## 新增项目模块

JFoenix 已纳入 `JFoenix` 本地模块，使用 `project(':JFoenix')`，不再依赖 Maven 发布包。上游版本和维护约定见 `JFoenix/README.md`；该模块的资源、许可证及名称保留规则已接入发行打包流程。

- 在 `settings.gradle` 中注册模块，并为模块创建 `build.gradle` 和 `module-info.java`。
- 在使用方 `build.gradle` 增加 `project(...)` 依赖，同时在 `module-info.java` 增加对应的 `requires`；跨模块使用的包按需声明 `exports`，反射访问的包按需声明 `opens`。
- 当前打包流程在 `gradle/packaging-tasks.gradle` 的 `projectJars` 中显式列出项目模块。新增模块参与发行包时，需要把它的 JAR 加入该列表。
- 新模块只有在访问 JDK 或 JavaFX 内部 API 时才需要调整 `packageVmOptions`，不要为常规模块重复添加 VM 参数。
