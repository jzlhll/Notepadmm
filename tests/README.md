# 大文件日志生成器

在项目根目录执行，不带参数时只显示帮助，不生成日志：

```bash
sh tests/generate_logs.sh
```

生成 100 万行：

```bash
sh tests/generate_logs.sh --lines 100w
```

执行生成时，默认保存到当前用户目录的 `Downloads/generated/log-1000000.log`：macOS 为 `~/Downloads/generated/`，Windows 通常为 `C:\Users\用户名\Downloads\generated\`。macOS 使用 `HOME`，Windows 的 Git Bash 优先使用 `USERPROFILE` 定位，目录不存在时自动创建；不跟随 Windows 下载目录的自定义重定向位置，可用 `--output` 指定该位置。

指定目标行数、输出路径及随机种子：

```bash
sh tests/generate_logs.sh --lines 500w --output ~/Downloads/generated/log-5000000.log --seed 42
```

指定起始时间：

```bash
sh tests/generate_logs.sh --lines 100k --start '2026-10-10 15:44:52.956'
```

- `--lines`：正整数，可带 `w`／`W`（万，乘以 10000）或 `k`／`K`（千，乘以 1000）后缀。例如 `100w` 为 100 万行，`100k` 为 10 万行。默认 `1000000`；换算后最多接受 `12000000` 行（`1200w` 或 `12000k`），大小限制和确认规则均按换算后的行数判断。正常完成时输出恰好为指定行数。
- `--output`：默认输出到当前用户目录的 `Downloads/generated/log-行数.log`；显式传入的相对路径按当前工作目录解析。
- `--seed`：`0`～`2147483646` 的整数，默认由当前时间及进程号生成；固定种子及其他参数可复现相同内容。
- `--start`：起始时间，格式为 `年-月-日 时:分:秒.毫秒`。
- `--force`：允许覆盖已有输出文件；默认遇到同名文件会停止。
- `--help`：查看参数帮助。

默认输出文件名使用换算后的完整行数，例如 `--lines 100w` 保存为 `log-1000000.log`。

## 大小与磁盘保护

单个输出文件的硬上限为 **3 GB（3,000,000,000 字节）**，目标行数的硬上限为 **1200 万行**。`--force` 仅允许覆盖同名文件，不绕过大小、磁盘检查或交互确认。所有 GB 均按十进制计算。

- 生成前按每行 **250 字节**估算：基于约 200 字节每行的实际观察，预留 25% 余量。例如 600 万行预估 1.5 GB，800 万行预估 2 GB；超过 1200 万行直接拒绝，不创建输出文件。
- 打开或覆盖文件前检查目标磁盘的可用空间，**不超过 5 GB 时直接拒绝**。超过时，扣除 **5 GB** 预留空间后与 3 GB 取较小值作为本次写入预算；预估大小超过该预算，或无法获取磁盘空间时停止。例如可用空间 6 GB 时，本次最多使用 1 GB。
- 硬限制检查通过后，**预估超过 1 GB（超过 400 万行）**或**磁盘可用空间少于 10 GB**时，依次显示目标行数、当前可用空间和预估生成大小，要求执行者输入 `y` 或 `yes` 确认。两种条件同时满足时合并为一次提示；空输入、其他输入或输入结束均取消。非交互环境直接拒绝，不提供免确认参数。
- 确认通过后再次检查磁盘预算，等待确认期间空间变得不足时仍会拒绝；确认前不创建或覆盖输出文件。
- 生成过程中按实际 UTF-8 正文字节数累计，并计入换行预算；macOS 每行计 1 字节换行，Windows 按可能的 CRLF 保守计 2 字节。写入下一行会超过预算时立即停止，以非零状态退出并保留已生成的完整行。实际大小受到中英文和长日志比例影响，预估不保证精确。

磁盘预算基于正式生成前的可用空间，其他程序同时写入磁盘仍会影响剩余空间。多个日志文件不会自动清理，各次运行都会按当时的剩余空间重新检查。

## 内容与搜索

日志采用示例中的时间、进程与线程、标签、应用包名、级别及正文列结构。全部应用、域名、标识符及业务内容均为虚构值；只生成文本，不访问网络或读取真实日志。混合中英文正文，文件使用 UTF-8；macOS 为 LF 换行，Windows 的换行输出取决于本机 `awk`。

标签包含 `MQTT`、`Api`、`Database`、`FileWatcher`、`ImageLoader`、`UploadWorker`、`SyncService`、`ConnectivityMonitor`、`DownloadManager`、`DiskCache` 等。应用包名随机选择 `com.example.photolab`、`com.example.notebox`、`com.example.syncservice`、`com.example.mediastore`，概率分别为 70%、10%、10%、10%；系统日志使用 `com.example.systemservice`。每个应用包名使用固定进程号，系统日志使用独立进程号。

时间不倒退，密集时段的随机间隔为 **0～4 毫秒**，允许相邻多条日志使用相同时间。普通时段间隔 10～800 毫秒，稀疏时段间隔 1～30 秒，时段之间偶尔间隔数十秒至十分钟。日志有长有短，长 JSON 日志为 600～1500 字符；每行连同时间及其他列最多 1500 字符，不含换行符。中文 UTF-8 字节数与字符数不同。

除百分比标记外，内容按以下概率随机选择；实际条数会有波动，小文件可能没有稀有事件：

| 类型 | 概率 | 搜索示例 |
| --- | --- | --- |
| 高频固定正文 | 80% | `trimMemory level: 5`、`heartbeat acknowledged`、`缓存命中` |
| 普通动态正文 | 16% | `request [`、`scan progress`、`扫描进度` |
| 长 JSON 正文 | 3% | `"detail":`、`scan batch completed` |
| 低频警告 | 0.99% | `NETWORK_TIMEOUT`、`INDEX_RETRY`、`CACHE_EVICT` |
| 稀有错误 | 0.01% | `RARE_EVENT`、`CHECKSUM_MISMATCH`、`TOKEN_EXPIRED` |

目标行数不少于 100 时，在 10%、20%……100% 位置各生成一条 `SEARCH_AHCHOR：百分比%` 日志，例如 `SEARCH_AHCHOR：10%`。位置按目标行数乘以百分比向上取整，标记替换该位置的普通日志并计入总行数；100% 标记位于最后一行。目标行数少于 100 时不生成这些标记。

日志由单个 `awk` 进程生成，整个生成过程只打开一次输出文件，按行流式写入，内存不会随目标行数增长。结束后输出文件大小、随机种子、分类条数和时间范围。中断时保留已写入的部分文件。

## 运行环境

单个 `.sh` 脚本，使用 shell 和系统工具 `awk`，macOS 可直接运行。随机数、日期递增、UTF-8 字符计数均在脚本内处理，兼容 macOS 的系统 `awk` 与 Git Bash 的 `awk`。

Windows 在 Git Bash 的项目根目录执行相同命令：

```text
sh tests/generate_logs.sh --lines 1000000
```
